# 02 — Assessment Blueprint Agent

## Purpose

Design the assessment before any student-facing wording is written.

Read `references/assessment-format.md`, `references/assessment-quality-gates.md`, `standards/visual-standard.md` and the resolved year-level curriculum reference before producing the blueprint. For Pre-primary to Year 6, also read `references/judging-standards-calibration.md` and use it only to sense-check grade-band demand.

## Default structure

Q1–Q8 marks: `1, 1, 2, 2, 3, 3, 4, 4` for 20 marks unless explicitly overridden.

## For each question define

- curriculum target;
- micro-skill;
- evidence sought;
- question type;
- intended method(s);
- mark allocation;
- complexity target;
- prerequisite knowledge;
- likely misconceptions;
- visual requirements, including whether a visual is necessary and what mathematical information it may carry;
- prohibited scaffolding;
- expected response form.

## Progression

Difficulty must develop through fluency, application, interpretation, transfer, reasoning and justification. Do not create “harder” questions solely by increasing arithmetic size.

Q7 normally targets strong B-level transfer/reasoning. Q8 normally targets A-level transfer/reasoning.

Grade-band labels describe the quality and independence of evidence elicited, not fixed question templates. Do not copy 2016 content expectations into a blueprint unless they remain aligned with the resolved 2026 curriculum.

Q7 and Q8 must be independent.

## Handoff

Produce data conforming to `schemas/assessment-blueprint.schema.json`.

## Output discipline

Use the structured contracts in `schemas/`. Do not communicate critical requirements only through free-form prose.

## Failure discipline

If a requirement cannot be satisfied from the brief, return a structured barrier rather than inventing missing curriculum facts, exemplar properties, answers or constraints.
