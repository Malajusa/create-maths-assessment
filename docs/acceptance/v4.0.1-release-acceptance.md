# v4.0.1 release acceptance matrix

This document defines the minimum target-environment evidence required before v4.0.1 is treated as production-proven. Scenario descriptions, unit tests and synthetic fixtures do not count as execution results.

## Case A — new v4 assessment end to end

Recommended representative task: Year 6 Volume and Capacity.

Required outcome: the complete `criterion_component_estimate_v1` workflow runs through stages 01–07 and the controller reports `READY` with zero open barriers.

Retain the actual:

- assessment brief and blueprint;
- generated Q1–Q6 and Q7–Q8 stage outputs;
- content-validation record and immutable approved question set;
- assessment specification;
- Student Test PowerPoint;
- Marking Key PowerPoint;
- Curriculum Rationale PDF;
- QA ledger;
- design manifest;
- separate generator and reviewer execution records;
- one full-resolution PNG per page for all three deliverables;
- independent render-review record;
- fresh package-audit report; and
- final controller status output.

The reviewer execution must be genuinely distinct from the generating execution. A role rename within one execution does not satisfy this case.

## Case B — exact-source key preservation

Input an existing assessment and request a marking key only.

Required outcome:

- source filename and SHA-256 are recorded;
- the key is produced from the exact supplied assessment rather than reconstructed from memory;
- wording, numbers, diagrams, order and base layout are preserved; and
- no unnecessary replacement Student Test or Curriculum Rationale is generated unless explicitly requested.

## Case C — equivalent Version B / re-attempt

Input an existing assessment and request an equivalent re-attempt.

Required outcome:

- source architecture is preserved unless migration is explicitly requested;
- constructs, demand, representation type and mark scheme remain equivalent;
- changed values are independently solved and propagated consistently to the key; and
- a v4 source preserves the 25-mark total, 5D / 8C / 5B / 7A envelope and indicative cut-offs.

## Case D — architecture barrier

Request a Years 3–10 assessment whose authorised curriculum scope cannot honestly support the canonical v4 evidence envelope without artificial mark splitting or unauthorised content.

Required outcome: the workflow stops with a concrete architecture barrier. It must not inflate evidence bands, add unauthorised curriculum content or silently alter the user's request to force a 25-mark package.

## Release decision

Cases B–D are regression confidence. Case A is the minimum case required to close the production-acceptance evidence gap identified during the v4.0.0 readiness review.

Do not convert a passing repository CI run into a claim that any of these cases has executed. Store real target-environment evidence and subject the resulting change set and evidence to independent Skill Craft re-review before approval.
